# PART: COMPLETE GAME SYSTEMS OVERVIEW

## Game Architecture

### Core Loop
1. Setup — choose origin, choose hustle, deal 7 cards
2. Round Start — draw scenario, roll Cipher, apply effect
3. Play Phase — each non-judge player selects 1 card, submits face-down
4. Judge Phase — judge reveals submissions, picks winner
5. Result Phase — winner gains +1 score, draws Receipt, stats update
6. Check Win — first to 7 points wins
7. Cookout Phase — every 3 rounds, alliances available

### State Machine
- setup → playing → judging → result → (next round) → game over
- Cookout phase inserts every 3 rounds
- Cipher effects override normal flow temporarily

### Card Database
- 200 Black scenarios
- 350+ White responses
- 100 Receipts
- 12 Ciphers
- 8 Origins
- 8 Hustles
- 24 Locations

### Save Format
JSON with full game state, receipts history, player progression

### Accessibility
- All cards: role="button", tabindex="0", aria-label
- Keyboard nav: Tab + Enter/Space + Escape
- Reduced motion: detect, replace animations with fades
- Contrast: minimum 4.5:1
- Skip links on every screen

### Multiplayer
- Room codes: 4-character alphanumeric
- WebSocket real-time sync
- Turn enforcement server-side
- Reconnection with state sync
- Pass-and-play offline fallback

## Implementation Order

1. Card database JSON
2. Character creation screen
3. Main game board
4. Judge phase
5. Round result
6. Block map
7. Cookout alliance
8. Game over
9. Animations

- No stereotypes, no performative slang
